# ふたりの作業ボード

2人の開発者で小さなタスクを分け合うための、シンプルなボードです。HTML・CSS・JavaScriptだけで動き、追加のインストールはありません。

## 使い方

1. このリポジトリを clone します。
2. ローカルだけで使う場合は `index.html` をブラウザーで開きます。
3. オンライン共有を使う場合は、下記のローカルサーバーを起動して `http://localhost:8000` を開きます。
4. タスクを追加し、担当と進み具合を選びます。

開発中はリポジトリのフォルダーで `python -m http.server 8000` を実行し、`http://localhost:8000` を開く方法も使えます。

## Supabaseで共有する

オンライン共有は、Supabase AuthとPostgresを使います。初回だけ次の設定が必要です。

1. Supabase SQL Editorで [supabase-schema.sql](supabase-schema.sql) の内容を実行します。ボード・メンバー・タスク用テーブルと、メンバーごとのRow Level Securityを設定します。
2. Authentication の URL Configuration で Site URL を `http://localhost:8000` に設定します。
3. 各メンバーがオンライン共有パネルからメールアドレスとパスワードでアカウントを作成し、確認メールのリンクを開きます。
4. ひとりが共有ボードを作成して招待コードを発行し、もうひとりへ安全な方法で伝えます。相手はサインイン後にそのコードで参加します。

SupabaseのProject URLとpublishable keyは [supabase-config.js](supabase-config.js) に設定済みです。publishable keyはブラウザーで使う公開キーです。アクセス制御はSQLで有効にするRLSが担います。secret keyやservice-role keyはフロントエンドに置かないでください。オンライン共有にはインターネット接続が必要です。

## 2人でGitHubを使う

- 変更ごとに `feature/短い説明` のようなブランチを作り、`main` に直接コミットしない。
- 作業を終えたらPull Requestを作り、もう1人が差分を確認してから取り込む。
- 最初の作業は、ひとりが画面の見た目、もうひとりがタスクの操作や説明文を担当すると分けやすいです。
- 共通の作業項目はGitHub Issuesに書き、担当者を決めてから着手します。

詳しくは [CONTRIBUTING.md](CONTRIBUTING.md) を参照してください。

機能一覧と共有ボードの設定手順は [FEATURES.md](FEATURES.md) を参照してください。

## 保存について

ローカルボードのタスクは開いたブラウザーのローカルストレージに保存されます。オンライン共有ボードを選ぶと、選択中のボードのタスクはSupabaseに保存され、同じボードのメンバーへリアルタイムで反映されます。ローカルデータは共有ボードへ自動送信されません。「ローカルタスクを追加」操作を使って明示的に移してください。

## 現在の機能

- タスクの追加、編集、削除
- 「これから」「進行中」「完了」の移動
- 開発者 A / B の担当割り当て
- タイトル・メモの検索と担当者での絞り込み
- 同じブラウザーの別タブとの変更反映
- タスクデータのJSONバックアップ書き出しと読み込み
- タスクの優先度設定、期限表示、優先度順の並べ替え
- カンマ区切りラベルとラベルでの絞り込み
- カードのドラッグ＆ドロップ移動と削除の取り消し
- Supabase Authを使ったサインイン、共有ボード、招待コード、リアルタイム同期

## バックアップ

「バックアップを書き出す」からタスクをJSONファイルとして保存し、「バックアップを読み込む」から復元できます。読み込みは現在のタスクを置き換えるため、確認画面が表示されます。ブラウザー間でタスクを移す場合は、元のブラウザーで書き出し、移行先で読み込んでください。
